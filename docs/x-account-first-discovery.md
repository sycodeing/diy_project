# X 账号证据待审模式

后台 `/admin/x-lead-search` 的“账号证据”表单需要管理员输入已核实的 X 原帖 ID/链接及核实依据。该入口仅手动创建 `account_first` 任务；默认定时筛选配置保持原状。只有 1.19.0 及以上发现 worker 可以领取新任务。

采集顺序固定为原帖详情一页、该帖回复一页、最多四位不同回复作者各一页近期本人帖。使用作者 ID 去重；其余真实参与者保留为待补证账号。一次最多六个付费请求，按每条 15 credits 保守预留 15 + 20×15 + 4×21×15 = 1575 credits（含可选置顶帖），上限 1800 credits，余额保底 3000。每个请求前记 attempt，成功响应在分类前写入本机 `.data/twitterapi/runs/account-first-*.json`。鉴权、业务错误、超时、额度异常均停止后续付费；不会自动重试。

账号评估仅使用该作者自己的回复和近期原帖。本人宠物叙述加另一独立帖子中的个性化/自用装饰行为可进入 `potential`；仅晒宠为 `watch`。购物意向默认 `unknown`。同一帖子重复出现在回复、时间线或置顶帖，只算一条证据。种子帖和商家提供的商品图仅作上下文，不证明回复者身份、购买意向、照片归属。当前交流入口由作者自己的帖子单独评估；`potential` 可以没有合适入口，已完成同类需求另列。所有草稿/人工批准/联系权限保持关闭。

后台 `/admin/x-leads?mode=account_review` 按稳定作者 ID 分页，仅显示最新评估，并可按账号状态、入口状态和人工状态组合筛选。账号来源历史保留批次与原帖 ID。忽略/恢复由管理员执行；原子数据库 upsert 不覆盖人工状态和首次发现时间。旧帖子待筛与严格候选仍在原视图；此模式不会导入 `x_leads` 或触发任何发送队列。表为空只表示尚未运行新模式，不能据此推断旧数据不存在。

本次改造的验证仅为 Mock/本地构建；尚无新模式真实采集、图片语义、账号适配效果或浏览器登录验收。生产 migration 建立空账号表和受限 RPC，不回填旧帖子，也不启动任务。
