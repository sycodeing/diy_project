# Account-first timeline credit reuse

The latest linked test spent 930 observed TwitterAPI credits: three `last_tweets` pages with 20 returned items each account for 900, and one two-item replies page accounts for 30. This was a linked replay, so its already archived exact seed was not fetched again. [TwitterAPI's published pricing](https://twitterapi.io/pricing/details) bills these endpoints at 15 credits per returned item, with a 15-credit minimum. Reducing local classification from 20 items to five after retrieval would not reduce that bill.

Account-first now caches only a successful, structurally valid raw `last_tweets` page for six hours. The key covers the API base URL, credential fingerprint, endpoint, author ID, and every request parameter. A valid hit reuses the original page in a new archive with the source archive ID, request index, and original response time. It does not extend the original expiry. Exact-seed and replies requests remain fresh. Each run still obtains a new contacted snapshot and applies its current 14-day window and classifier to the raw posts. Invalid, failed, expired, future-dated, wrong-author, or mismatched pages are fetched anew; a cache failure cannot approve an account.

For a repeated 20-item timeline within six hours, the estimated avoided provider charge is 300 credits; the first fetch saves nothing. `paid_requests`, `timeline_cache_hits`, `estimated_avoided_credits`, and the archive's `cache_reuses` make the distinction auditable. The estimate is not a provider settlement. The 1,575-credit static plan remains the worst-case bound, while each paid request now reserves only when it is needed. The 3,000-credit floor still stops an uncached request before it is sent. Set `TWITTERAPI_ACCOUNT_TIMELINE_CACHE_HOURS=0` to disable reuse, or `TWITTERAPI_ACCOUNT_TIMELINE_FORCE_REFRESH=true` to refresh a specific worker run. A running worker needs a controlled restart before it loads these new settings; no worker restart or live provider test was done for this code-only change.

Validation: Python suite passed using mocked provider responses, including repeated author across seeds, latest contacted exclusion, cache isolation, expiry, corruption, wrong author, force refresh, and low-balance hit/miss behavior. Actual future savings depend on revisiting the same author within six hours; this local test does not establish a live savings rate or improve buyer qualification.
