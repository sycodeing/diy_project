## 固化的采集策略

- `probe_purchase_intent.py --recall` 调用可复用的 `probe_purchase_recall.run_recall_probe`；原有严格筛选模式保留。
- 默认最近三天、Latest，先宽商品主题，再独立买家措辞；空页或全重复页切换查询，在限制内继续寻找新帖子。已达到新帖目标时仍保留一次独立买家措辞验证。
- 通用 `dog` 控制页只在显式 `--diagnose-control` 时运行，不在每次采集中重复付费。
- 查询保留回复，原始帖子和父帖 ID 不会因缺地区或照片被丢弃。未获取的父帖标为未解决，不用它推断购买需求。
- 每页先保存完整原始响应，再检查时间、历史重复及文本需求；无效日期、超出时间窗和重复结果不能计入近期新增目标。
- API 错误与有效空结果分别记录；预算、页数、余额和失败停止状态写入档案。
- 输出区分新原帖、正文词语相关、匹配文本需求和严格候选。严格候选不能由这个原始召回模式直接产生。

这是已执行验证的命令行采集入口；后台 worker 默认查询及网页任务入口没有自动切换，也没有新增定时运行。
